Paper summary — Histograms of Oriented Gradients for Human Detection (Dalal & Triggs, 2005)

Goal

  • Evaluate feature sets for robust human (pedestrian) detection using a linear SVM baseline; introduce and analyze dense, locally normalized Histograms of Oriented Gradients (HOG) descriptors.

Key idea

  • Represent a detection window by a dense grid of local histograms of gradient orientations (HOGs) computed on small spatial cells, contrast-normalized over overlapping larger blocks, then classify with a linear SVM.

Datasets & methodology

  • MIT pedestrian dataset (509 train, 200 test images) — near-perfect separation achieved.
  • INRIA dataset (introduced here): 1805 cropped 64×128 person images (more pose/background variation); 1239 positives used for training (plus left-right reflections) and a large set of hard negatives mined from 1218 person-free photos.
  • Performance measured with DET curves (miss rate vs false positives per window, FPPW); reference metric: miss rate at 10−4 FPPW.

HOG descriptor pipeline (overview)

  1. Input image (RGB/LAB or grayscale; square-root gamma improves low-FPPW slightly).
  2. Compute gradients per pixel (best: centred [−1,0,1] filter, no smoothing; for color, take channel with largest gradient magnitude).
  3. Spatial & orientation binning:
    • Cells: accumulate weighted votes into orientation bins (bilinear interpolation in position and orientation).
    • Vote weight: gradient magnitude (best), not binary edge presence.
    • Orientation: unsigned (0°–180°) works best for pedestrians; ~9 orientation bins recommended.
  4. Blocks & normalization:
    • Group cells into larger overlapping blocks; normalize block vectors (L2-Hys, L2 or L1-sqrt perform well).
    • Overlap (stride half cell) so each cell appears multiple times with different normalizations — improves performance.
  5. Concatenate normalized block descriptors over the 64×128 detection window; train linear SVM (C≈0.01). Kernel SVM yields modest gains (~3% at 10−4 FPPW) at much higher cost.

Key implementation choices and findings (quantitative effects)

  • Gradient computation: finest scale (no smoothing) with centred [−1,0,1] best; smoothing reduces recall significantly.
  • Orientation bins: performance improves up to ~9 bins (0°–180°); signed 0°–360° reduces performance for pedestrians.
  • Cell size & block geometry: best typically 8×8 pixel cells with 2×2 or 3×3 cell blocks (authors’ default: 8×8 cells, 16×16 blocks made of 2×2 cells); 3×3 of 6×6 cells also performed well in some tests.
  • Block overlap: overlapping blocks (e.g., stride = cell size/2) improves miss rate ~4–5% at 10−4 FPPW.
  • Normalization: L2-Hys (Lowe clipped L2) or L1-sqrt recommended; no normalization drastically degrades performance (~27% worse).
  • Input color/gamma: RGB or LAB slightly better than grayscale (~1.5% at 10−4 FPPW); square-root gamma gave ~1% improvement at low FPPW.
  • Detector window context: including ~16 pixel margin around person (64×128 window) helps; reducing margin degrades performance.
  • Classifier: linear SVM is fast and strong; kernel SVM gives small improvement at much higher cost.

Comparisons and results

  • HOG (rectangular R-HOG and circular C-HOG variants) substantially outperforms Haar-wavelet, PCA-SIFT, and Shape Context based detectors on MIT and INRIA datasets — large reductions in false positives per window.
  • Binary edge voting or omitting orientation information significantly reduces performance.
  • Overlapping normalized HOGs give near-perfect results on MIT and strong results on INRIA.

Explanations / insights

  • Fine-scale edges provide most discriminative information; smoothing loses useful cues.
  • Fine orientation resolution + coarse spatial resolution best for pedestrian shapes (limb width ~6–8 pixels in authors’ images).
  • Overlapping block normalization supplies redundant but useful contrast-normalized versions of each cell, improving robustness to illumination and background clutter.
  • Trained SVM weights show detectors cue mainly on silhouette contours (head, shoulders, feet), with positive weights outside contour normalizing contrast and negative weights inside person reducing false positives.

Formulas / algorithmic specifics

  • Gradient filters: centred finite differences [−1, 0, 1] (no smoothing).
  • Orientation voting: bilinear interpolation in orientation and spatial position; vote weight = gradient magnitude (or other tested variants).
  • Normalization variants:
    • L2-norm: v ← v / sqrt(||v||_2^2 + ε^2)
    • L2-Hys: L2 norm, clip components to 0.2, renormalize
    • L1-norm: v ← v / (||v||_1 + ε)
    • L1-sqrt: v ← sqrt( v / (||v||_1 + ε) )
  • SVM kernel (when used): Gaussian RBF exp(−γ ||x1 − x2||^2); linear SVM used by default (C≈0.01).

Practical defaults (authors’ recommended configuration)

  • Input: RGB (or LAB), optional square-root gamma.
  • Gradient: centred [−1,0,1], σ=0 (no smoothing); per-channel, keep max magnitude channel_
  • Cells: 8×8 pixels.
  • Orientation bins: 9 bins over 0°–180° (unsigned).
  • Blocks: 2×2 cells (16×16 pixels), Gaussian spatial weighting (σ = 0.5 * block width), block stride = 8 pixels (50% overlap), L2-Hys normalization.
  • Detection window: 64×128 pixels (person ~48×96 with margin).
  • Classifier: linear SVM (C=0.01); hard-negative mining with retraining.

Limitations & future work

  • Fixed-template detector limits articulation handling; parts-based HOG models could help for highly articulated or heavily occluded humans.
  • Efficiency: kernel SVMs are slower; opportunities exist for coarse-to-fine or cascade detectors for real-time speedups.
  • Extensions: incorporating motion (optical flow/block matching) for video-based detection_

Conclusion

  • Densely sampled, locally normalized HOG descriptors combined with a linear SVM form a simple, effective, and robust method for pedestrian detection that significantly outperforms prior wavelet- and shape-based methods; fine gradient scale, fine orientation binning, overlapping block normalization, and coarse spatial bins are the main contributors to strong performance_

HOG cheatsheet — defaults & quick pseudocode

Parameters (authors’ default)

  • Input: RGB (or LAB). Optional per-channel sqrt(gamma).
  • Gradient: centred 1-D filter [−1, 0, 1], no smoothing (σ=0). For color: compute per-channel gradient, pick channel with largest magnitude.
  • Detection window: 64 × 128 pixels (person centered, ~16 px margin).
  • Cell size: 8 × 8 pixels.
  • Block size: 2 × 2 cells (16 × 16 pixels).
  • Block stride: 8 pixels (50% overlap → each cell appears in 4 blocks).
  • Orientation bins: 9 bins, unsigned (0°–180°).
  • Spatial weighting: Gaussian within block, σ = 0.5 × block_width.
  • Vote weight: gradient magnitude (no clipping).
  • Block normalization: L2-Hys (L2-norm, clip at 0.2, renormalize); ε small (e.g., 1e-6).
  • Classifier: linear SVM (C = 0.01). Hard-negative mining: 1 retrain iteration using false positives from negative images.
  • Evaluation metric: DET; reference miss rate at 1e-4 FPPW.

Pseudocode (feature extraction per detection window)

function HOG_descriptor(image_window):    # image_window: 64x128 RGB (or LAB), float intensities    # 1. optional sqrt-gamma    for each channel: channel = sqrt(channel)
    # 2. gradients    for each channel:        Gx = convolve(channel, [-1,0,1] along x)        Gy = convolve(channel, [-1,0,1] along y)        Mag_ch = sqrt(Gx^2 + Gy^2)        Ori_ch = atan2(Gy, Gx)   # radians    # choose channel per-pixel with max magnitude    Mag = max_over_channels(Mag_ch)    Ori = corresponding_orientation_in_degrees(Ori_ch)    # use unsigned orientation: Ori = Ori mod 180
    # 3. cell histograms    num_cells_x = window_width / cell_width  # 8    num_cells_y = window_height / cell_height # 16    initialize cell_hist[cell_y][cell_x][9] = 0    for each pixel (x,y):        # spatial bilinear weights into neighboring cells        find surrounding cell centers and compute spatial weights (bi-linear)        # orientation bilinear interpolation between two nearest bins        bin_f = (Ori / 180) * num_bins        bin_low = floor(bin_f) mod num_bins        bin_high = (bin_low + 1) mod num_bins        w_bin_high = bin_f - floor(bin_f)        w_bin_low = 1 - w_bin_high        for each affected cell:            cell_hist[cell_y][cell_x][bin_low]  += Mag * w_cell * w_bin_low            cell_hist[cell_y][cell_x][bin_high] += Mag * w_cell * w_bin_high
    # 4. block normalization (overlapping)    block_stride_cells = block_size_cells / 2  # stride=1 cell (since block=2x2 cells)    descriptor = []    for by in 0 .. num_cells_y - block_size_cells step block_stride_cells:        for bx in 0 .. num_cells_x - block_size_cells step block_stride_cells:            v = concatenate cell_hist for cells in block (size = block_cells * num_bins)            # apply Gaussian spatial weighting to pixels was done earlier; optionally weight cells by Gaussian            # L2-Hys normalization            v = v / sqrt(sum(v^2) + eps^2)            v = clip(v, 0, 0.2)            v = v / sqrt(sum(v^2) + eps^2)            append v to descriptor
    return flatten(descriptor)  # final feature vector

Implementation notes / tips

  • Use efficient integrals or optimized convolution loops; compute gradients once per pyramid level.
  • Store features as floats; dimensionality ~ ( ( (num_cells_x - 1) * (num_cells_y - 1) ) * block_cells * num_bins ). For 64×128, 8×8 cells, 2×2 blocks, 9 bins → descriptor length = 715 * 49 = 3780.
  • Use float eps ~ 1e-6 to avoid division by zero.
  • Hard-negative mining: one retrain pass suffices (authors).
  • For speed, precompute orientation bin centers and interpolation weights; vectorize loops or use SIMD.

Find the bounding box of the foreground with NumPy only. # Hint: The symbols are dark, the background is bright. # Allowed: NumPy operations such as argwhere, min, max, slicing. # Not allowed: cv2.findContours, connectedComponents, or similar high-level localization helpers.

Assuming input is a 2D NumPy array img (dtype uint8/float) where foreground (symbols) is darker than background, you can find the minimal axis-aligned bounding box of the foreground like this:

import numpy as np
def bbox_of_dark_foreground(img, threshold=None):    # img: 2D array (grayscale). Foreground = darker pixels.    # threshold: optional scalar. If None, use Otsu-like automatic threshold via mean.    if threshold is None:        # simple automatic threshold: mean or a fraction of mean works robustly        threshold = img.mean()  # foreground < threshold
    # boolean mask of foreground pixels (darker than threshold)    fg = img < threshold
    # if no foreground found, return None or an empty box    if not fg.any():        return None  # or (0,0,0,0)
    # get coordinates of foreground pixels (row, col)    ys, xs = np.argwhere(fg).T
    ymin, ymax = ys.min(), ys.max()    xmin, xmax = xs.min(), xs.max()
    # return as (xmin, ymin, xmax, ymax) or (ymin, xmin, ymax, xmax) as needed    return (xmin, ymin, xmax, ymax)

Notes:

  • If the image has some illumination variation, use a more robust threshold, e.g. threshold = np.percentile(img, 90) or threshold = img.mean() * 0.95, depending on contrast.
  • For binary input (0/1) use fg = img == 1 or img.astype(bool).
  • The returned box is inclusive; to use for slicing do img[ymin:ymax+1, xmin:xmax+1].

To resize the cropped ROI so it fits within half the canvas (keeping aspect ratio), compute the target max size = half of canvas width and height, scale the ROI down if needed, and use cv2.resize.

Example (concise):

import cv2import numpy as np
# inputs:# roi: 2D NumPy array (grayscale) from previous crop# canvas_shape: (height, width) of the canvas image
def resize_to_half_canvas(roi, canvas_shape, interp=cv2.INTER_AREA):    ch, cw = canvas_shape    max_h = ch // 2    max_w = cw // 2
    h, w = roi.shape    if h == 0 or w == 0:        return roi  # empty
    # compute scale to fit within (max_w, max_h) while preserving aspect ratio    scale = min(1.0, min(max_w / w, max_h / h))  # <=1: don't upscale    new_w = max(1, int(round(w * scale)))    new_h = max(1, int(round(h * scale)))
    resized = cv2.resize(roi, (new_w, new_h), interpolation=interp)    return resized

Notes:

  • This prevents upscaling (scale ≤ 1). If you do want to allow upscaling, remove min(1.0, ...).
  • Use INTER_AREA for downscaling; use INTER_LINEAR or INTER_CUBIC if upscaling is allowed.

import numpy as np
def place_center(resized, canvas_shape, background=255):    ch, cw = canvas_shape    canvas = np.full((ch, cw), background, dtype=resized.dtype)
    h, w = resized.shape    # compute top-left corner so resized is centered    y0 = (ch - h) // 2    x0 = (cw - w) // 2
    # clamp in case resized is larger than canvas (shouldn't happen if resized fits)    y0 = max(0, y0)    x0 = max(0, x0)    y1 = min(ch, y0 + h)    x1 = min(cw, x0 + w)
    # corresponding region in resized    ry0 = 0 if y0 == (ch - h)//2 else (0 if h <= ch else (-(ch - h)//2))    rx0 = 0 if x0 == (cw - w)//2 else (0 if w <= cw else (-(cw - w)//2))    # Simpler: handle usual case where resized fits entirely:    canvas[y0:y1, x0:x1] = resized[0:(y1-y0), 0:(x1-x0)]
